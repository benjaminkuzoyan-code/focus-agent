1. The big picture

Focus Agent is a Chrome extension that reads your school portal's assignment list, ranks what you should do first, and coaches you through actually doing it — timers, check-ins, nudges when you drift to YouTube, and a chat coach that knows your real workload.

Three design rules shape everything:

Everything stays on your device

Assignments, sessions, and stats live in chrome.storage.local. Nothing is uploaded anywhere. That's the privacy story for parents and schools.

Works with or without AI

A rule-based coach always works. If the local bridge server is running, a real Claude brain takes over — same interface, zero UI changes.

Negotiate, don't block

It never blocks sites. It notices drift and talks to you about it, with receipts ("you said 4pm").

2. The five pieces of a Chrome extension

Chrome extensions aren't one program — they're several small programs running in different places that talk by passing messages. manifest.json is the map that tells Chrome what's what.

PieceFilesRuns whereCan do
Content scriptscontent.js, overlay/coach-overlay.js, plus the adapters/ and lib/ files listed in the manifestInjected into the portal page itself (Blackbaud, Canvas, …)Read the page, call the portal's API with your login cookies, draw on top of the page. Limited Chrome APIs (storage + messaging).
Service workerbackground.jsInvisible background process. Chrome kills it when idle and wakes it on events.Alarms, notifications, watching tabs, full Chrome API.
Side panelsidepanel/panel.html/.js/.cssThe tall panel docked to the right of the browserFull UI. Queries tabs, messages content scripts, reads storage.
Popuppopup/The little window when you click the toolbar iconOne-glance "what's next" + a Panic shortcut that opens the panel.
Manifestmanifest.json—Declares permissions, which URLs get content scripts, and in what order files load.

Why load order matters

Content scripts aren't modules — every file is just dumped into the same scope one after another. So the manifest lists adapters/schema.js first (it creates the global FA object), then the adapters, then lib/priority.js and lib/ai.js, then content.js, and finally the overlay. Every file starts with the same trick:

(() => {
  const FA = (globalThis.FA = globalThis.FA || {});   // grab or create the shared namespace
  FA.something = ...;                                  // hang your stuff on it
})();

That's an IIFE (immediately-invoked function expression): a function you define and call in one go, so its local variables don't leak into the page. FA is the one deliberate global. The service worker does the same thing with importScripts(...).

3. How assignments get from Blackbaud to you

Step by step, when you open the Assignment Center:

  1. Chrome injects the content scripts because the URL matches https://*.myschoolapp.com/* in the manifest. content.js logs [Focus Agent] v0.5.2 content script loaded.
  2. detectAdapter() in content.js asks each adapter matches(hostname). The Blackbaud one says yes for myschoolapp.com.
  3. The adapter calls the portal's own API — /api/DataDirect/AssignmentCenterAssignments/?format=json&filter=2&persona=2&dateStart=…&dateEnd=…. Because the request is made from the portal page, it carries your login cookies automatically. No password ever touches the extension.
  4. Normalize. Each raw item (snake_case keys like short_description, groupname, date_due) is turned into the standard Assignment shape by FA.makeAssignment(). Finished ones (assignment_status ≥ 1) are dropped.
  5. Cache. content.js fires a CACHE_ASSIGNMENTS message to the background worker, which saves the list to storage so the popup and side panel still work after you close the portal tab.
  6. The overlay (same page, same scope) calls fetchNormalized() directly, ranks the list, picks one, draws the bubble and pins badges on the matching portal rows.
  7. The side panel, when set to "portal", runs chrome.tabs.query() to find portal tabs and sends each one GET_ASSIGNMENTS; the content script answers with the fresh list. If no tab answers it falls back to the cache, then to demo data — and (as of today) tells you exactly why in the headline.
The gotcha that bit us today: Chrome only reads your files when the extension is (re)loaded. Editing adapters/blackbaud.js does nothing until you hit ↻ at chrome://extensions and refresh the portal tab — an already-open tab keeps its old content script (and can't answer the side panel's messages: "Receiving end does not exist").

The one shape everything uses

  title:   "PEChem HW #1",
  course:  "PolyEnriched Chemistry - 3",
  type:    "homework",              // test | project | essay | lab | homework | reading | other

  source:  "blackbaud",
  raw:     { ...the original API object, kept for debugging }
}

FA.normalizeType() in schema.js buckets whatever free text the portal uses ("Process", "Reading", "HW", null…) into those seven canonical types by regex. Type drives effort estimates and whether something counts as a "boss."

5. The two brains

All coaching goes through one object: FA.coach. It has methods like pick(ranked), panicPlan(ranked, minutes), breakdown(assignment), chat(messages, context), debrief(session), autopsy(sessions). There are two classes that implement them:

⚙️ MockCoach (rules)

Pure JavaScript, instant, always available. Picks the top-ranked item and writes a reason from a few templates ("Due in 16h and takes about 30m. The math says now."). Panic plan is a greedy value-per-minute schedule.

🧠 ClaudeCoach (real brain)

Extends MockCoach. Each method tries bridgeCall() to the local server first; if that fails or times out, it calls super.method() and you get the rules answer. Failure is invisible.

FA.initCoach() runs at startup: it pings http://localhost:8000/health. Answer → FA.coach = new ClaudeCoach() and the badge shows 🧠. No answer → rules, badge shows ⚙️. That's the "real brain is offline" message.

The UI never waits on Claude. renderToday() shows the rules pick immediately, then if the brain is Claude it fires the slow call and upgrades the text in place when it lands (that's the 🧠 prefix).

How ranking works (lib/priority.js)

  • estimateMinutes(a, sessions) — average of your past sessions on the same type of work; falls back to a base table (test 60, essay 50, homework 30…). So the estimates become yours over time.
  • urgencyScore(a) — time pressure from hours until due, plus points, plus a bit of effort. Overdue explodes the score.
  • rankAssignments() — filters out anything you've marked done, decorates with estMin/urgency, sorts descending.
  • findAvoided() — the "friend noticing" feature: things visible for 3+ days, due within 5, never started (or overdue and never started).

6. The bridge server (bridge/coach_server.py)

A tiny Python HTTP server on 127.0.0.1:8000 with two jobs: serve the project folder statically (so the demo portal works) and answer POST /coach.

cd ~/Projects/focus-agent
python3 bridge/coach_server.py     # leave this terminal open

For each /coach request it builds a prompt (one builder per method: build_pick, build_panic, build_chat…), then literally runs

claude -p --model sonnet --output-format json

as a subprocess. That's headless Claude Code — it uses your existing Claude login, so no API key. Each call spins up a fresh session (~5–20 s) and spends a bit of your plan quota. The extension can reach it because the manifest lists http://localhost:8000/* in host_permissions.

Because it shells out to claude, the bridge needs the network. Flaky wifi = timeouts = silent fallback to rules. If 🧠 never appears, check wifi before anything else.

The store build strips the bridge and the localhost permission entirely (see packaging) — store users get rules-only until a proper backend exists.

7. Feature by feature

Today tab

  • Focus Forecast (lib/forecast.js) — next 7 days as weather. Each day's minutes-due is bucketed: ☀️ clear, 🌤️ light, ⛅ busy, 🌧️ heavy, ⛈️ STORM. Tests count extra because they need lead-up study time. Generates one headline like "Thursday is a storm — start the essay Tuesday."
  • Coach pick — the one thing to do now, with a reason.
  • Avoidance card — appears when findAvoided() flags something. Offers a 2-minute micro-start (the research says the dread changes after you start) or a breakdown.
  • Smart Start (▶ on each card) — opens the assignment's URL, starts a focus session sized to the estimate (clamped 15–50 min), tells the background worker to schedule check-ins.
  • Doc Starter (essays/projects) — creates a titled Google Doc, puts the coach's outline on your clipboard, and remembers the doc URL so next click reopens it.

Panic tab

"I have 120 minutes tonight." The coach builds a schedule of time blocks ordered by value-per-minute and is honest about what doesn't fit ("sacrifices"). Claude version gets the full list; rules version is greedy.

Timer tab

  • Sessions with a ring timer; optional mood check-in (😃 😐 😬) whose answer changes the coach's response.
  • Check-ins — every N minutes (default 10) a notification asks "Still on it?" Honest "got distracted" is logged as a distraction, not punished.
  • Commitments — "start the essay at 4:00." The background worker polls every minute and fires a "Receipts 🧾" notification at the time you named.
  • Debrief — one line after each session (Claude-written when available).

Chat tab

Talks to FA.coach.chat() with the last 12 messages plus context: your top 8 ranked assignments and this week's stats. That's why it "knows" your workload — but only whatever the panel currently has loaded. Panel on demo data → coach on demo data.

Stats tab

Charts (lib/charts.js, hand-drawn SVG): focused minutes per day, what hours you actually focus, distractions per session, which sites cost you most (each ≈ 23 min refocus, per the UC Irvine research). Plus the autopsy: after 3+ sessions, patterns like "you focus best 7–9pm, Math sessions run 40% over estimate."

Quests tab (lib/xp.js)

1 focused minute = 1 XP; completing an assignment adds its estimated minutes as bonus. Level n needs n²×50 XP. Every test on the portal becomes a boss whose HP drains as you complete lead-up work and log study sessions for that course.

On-page overlay + ✏️ annotate

The bubble is a shadow-DOM widget (its CSS can't leak into or be broken by the portal's CSS). Badges are found by walking the page's text nodes for each assignment title; a MutationObserver re-applies them when Blackbaud's single-page app re-renders. The ✏️ chip injects annotate/annotator.js on demand via chrome.scripting so you can draw on any page.

8. What's stored, and where

Everything is in chrome.storage.local, wrapped by lib/storage.js (FA.store.*) so no other file touches raw keys.

KeyHolds
sessionsEvery finished focus session: what, when, planned vs actual minutes, distractions, mood
activeSessionThe one running now (or null) — background worker reads this to decide whether to nudge
commitments"Hold me to it" promises with dueAt, and whether kept/missed
questEventsCompleted quests and the XP they earned
assignmentMetaPer-assignment: done?, first seen (avoidance clock), doc URL, minutes spent
assignmentsCacheLast fetched list + timestamp — the offline fallback. Cleared on every extension reload.
settingsdataSource ("mock" = demo, "auto" = portal), session length, check-in interval
chatHistoryLast 40 chat messages

Assignment ids are the join key across all of this, which is why the id collision (all 17 items hashing to the same id) wiped out the whole list: one "done" flag applied to everything. Ids are now the portal's own (blackbaud-41491503).

9. The background worker (background.js)

Three jobs, all event-driven because Chrome may kill the worker any time it's idle:

  1. Check-ins — SESSION_STARTED creates a repeating alarm; each tick posts a notification with "Locked in 🔒 / Got distracted 😬" buttons.
  2. Distraction watcher — on every tab switch or URL change, if a session is active and the host matches DISTRACTOR_PATTERNS (youtube, tiktok, reddit…), it logs the drift and sends a negotiation notification. Rate-limited to one per 2 minutes so it isn't a nag.
  3. Commitment receipts — a 1-minute alarm checks for due commitments and fires the "you told me 4pm" notification. It marks notifiedAt before notifying so a crash can't double-fire.

It also answers messages: CACHE_ASSIGNMENTS, GET_COACH_STATE, START_SESSION_FROM_PAGE, END_SESSION_FROM_PAGE. Every handler does return true from the listener — that's Chrome's way of saying "I'll call sendResponse later, keep the channel open."

10. Loading, reloading, and packaging

Dev loop

  1. chrome://extensions → Developer mode → Load unpacked → pick ~/Projects/focus-agent. (Already done on this Mac.)
  2. Edit files.
  3. Hit ↻ on the extension card. Then refresh any portal tab — old tabs keep old content scripts.
  4. Side panel closes on reload; reopen it. Check the console for the version stamp.

Store build

bash scripts/package-store.sh     # → dist/focus-agent-<version>.zip

Copies an explicit allowlist of folders, deletes adapters/demo.js, and rewrites the manifest to remove every localhost reference. So the shipped extension has no bridge, no dev permissions, and can't be accused of phoning home. Mock data stays in so new users can try it before connecting a portal. Bump "version" in manifest.json before each build.
