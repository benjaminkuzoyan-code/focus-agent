1 · The four pieces

Focus Agent is not one program. It is three pieces of a Chrome extension that can only talk through messages, plus a separate Python server on your Mac that holds the model. Nothing else runs anywhere.

Why the content script exists

An extension page can't call the school's API with your session. A script injected into the myPoly tab can, because the browser attaches that tab's cookies. Everything portal-shaped starts there.

adapters/blackbaud.js · canvas.js · classroom.js

Why the bridge is a separate program

Chrome extensions can't run Python or hold a secret safely. The bridge keeps the model key (or your Claude login) on the machine, enforces who is a student and who is you, and turns every feature into one prompt builder.

BUILDERS = {pick, setup, chat, readScreen, …}

2 · Reading Blackbaud

Tapping ↻ in the panel asks the myPoly tab for assignments. The adapter calls the same JSON endpoints the portal page uses, normalizes each item into one Assignment shape, and fetches the teacher's attached links for anything still pending.

3 · Ranking the list

The panel never shows the raw feed. lib/priority.js scores every pending item, and the list pins the behind section on top, the ranked rest in the middle, and the year's finished work folded underneath.

5 · A coach call, end to end

Every smart feature is the same shape: the panel builds a small JSON payload, the client in lib/ai.js posts it to the bridge, the bridge decides who you are and builds the prompt, one model call happens, and the reply is validated before the panel trusts it.

6 · Eyes: how an image reaches the model

Four features share one path. What differs is where the pixels come from and which prompt the bridge builds. The annotation rule from the spec is applied server-side, from the assignment's own words.

7 · The clock: one session, two keepers

The running sitting lives in chrome.storage.local as activeSession. The panel draws it while open; the worker guards it while the panel is closed. Both read the same record, and that is where the timer race came from.

8 · What's stored where

9 · The test gates

Four suites run before every commit, and one boot test that clicks through the panel in a fake browser.

security_tests.py 89/89

Starts the bridge with a mock engine that reports what it would have sent. Proves origins, codes, roles, framing attacks, image validation, and every prompt rule: length cap, annotation rule, orientation only.

python3 scripts/security_tests.py

test-panel-boundary.js 28/28

Runs the real panel functions in a VM: developer controls only on a positive, current dev answer bound to the exact server and code.

node scripts/test-panel-boundary.js

test-background.js 14/14 · test-docops.js 17/17

Worker alarms and session end paths; the Google Docs edit ops (MLA format, replace, insert) with their index math.

npm test runs all four

smoke-panel.js 6 known failures

Boots the panel in jsdom with the fixture feed: list order, missing section, Smart Start opening links, folded replies. The six failures predate this week and are about the chunk checkpoint and dev toggle in jsdom.

node scripts/smoke-panel.js

What the gates can't see: a real scanned PDF, a real YouTube tab, the frames pass, the timer race, and whether the model actually respects the length cap. Those are your reload-and-try list.
